# Data Platform

Modern.js 的 Effect BFF 已支持基于请求信封（request envelope）的数据平台契约，适用于 Module Federation 与微前端场景下的稳定数据编排。

## 解决的问题

- Host / Remote 间稳定的操作标识（operation identity）。
- 按命名空间、来源、用户/租户隔离缓存键。
- 请求载荷与选择计划（selection plan）完整性校验。
- 服务端边界可选严格校验（strict mode）。
- 跨命名空间失效策略更安全（默认不跨应用）。
- 分布式链路追踪上下文连续传递。

## 运行时契约工具

可通过 `@modern-js/plugin-bff/data-platform` 使用以下能力：

```ts
import {
  createOperationId,
  buildScopeKey,
  buildQueryKey,
  createRequestEnvelope,
  validateRequestEnvelope,
  createHydrationEnvelope,
  validateHydrationEnvelope,
  createInvalidationEvent,
  shouldApplyInvalidation,
} from '@modern-js/plugin-bff/data-platform';
```

## Effect 运行时校验

可在 `modern.config.ts` 中开启严格的服务端 envelope 校验：

```ts title="modern.config.ts"
export default defineConfig({
  bff: {
    runtimeFramework: 'effect',
    effect: {
      dataPlatform: {
        requireEnvelope: true,
        expectedNamespace: 'my-app',
        selection: {
          maxDepth: 6,
          maxFields: 200,
        },
      },
    },
  },
});
```

当启用 `validateOrigin` 时，Effect 运行时会优先使用请求中的 `Origin` 头进行 origin 校验；若不存在 `Origin`，则回退到请求 URL 的 origin。

## Effect 客户端自动行为

使用生成的 Effect 客户端（`@api/effect/index`）时，Modern.js 会在同源请求中自动附加序列化的 envelope 请求头（`x-modernjs-data-envelope`）。

Envelope 默认包含：

- operation 元数据
- scope 缓存标识
- request mode
- selection plan 哈希
- 可选 trace 上下文

对于浏览器跨域请求，默认不会附加 envelope 请求头，以避免在跨项目/微前端场景下引入额外 CORS 预检失败。

若必须跨域携带 envelope 请求头，可设置 `request.dataPlatform.allowCrossOriginEnvelope = true`，并在服务端 CORS 中放行该请求头。

## 网络批处理

生成的 Effect 客户端默认会对 GET 请求启用微批处理。在同一短时间窗口内的请求会合并为一次对 `/_data/batch`（位于 BFF 前缀下）的 POST 调用，并保持逐条响应语义。

批处理特性：

- 默认仅批处理 GET（可通过 `allowedMethods` 调整）。
- 对相同请求进行 in-flight 去重。
- 当批处理端点不可用时自动回退为单请求。
- 条目级隔离：单条失败不会影响同批次其他条目。
- 保持链路追踪：批处理网关会从条目请求头或 envelope 元数据转发 `traceparent`。

服务端可通过 `bff.effect.dataPlatform.batch` 配置：

```ts title="modern.config.ts"
export default defineConfig({
  bff: {
    runtimeFramework: 'effect',
    effect: {
      dataPlatform: {
        batch: {
          endpoint: '/_data/batch',
          maxBatchSize: 16,
          maxBatchBytes: 64 * 1024,
          flushIntervalMs: 8,
          maxConcurrency: 4,
          requestTimeoutMs: 10000,
          allowedMethods: ['GET'],
        },
      },
    },
  },
});
```

## 推荐策略

- 保持 `validateOrigin` 开启。
- 为每个应用/远程模块配置 `expectedNamespace`。
- 客户端全部迁移后，在生产开启 `requireEnvelope`。
- 除非你能明确保证 mutation 顺序与幂等性，否则保持仅 GET 批处理。
- 在 MF 场景下，Host/Remote 各自维护本源 batch endpoint，不要将所有流量汇聚到单一共享源。
- 跨应用失效必须显式声明 `targetNamespaces`，并由订阅方显式 opt-in。

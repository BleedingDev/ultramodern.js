# ADR-0001: RsDoctor Default-On in Normal Builds

- Status: Implemented
- Date: 2026-02-21
- Decision Type: Framework default behavior

## 1. Context

RsDoctor is currently documented as opt-in due to build-time overhead. Team direction is to keep diagnostics simple and always available for humans and coding agents, including normal builds.

## 2. Decision

Enable RsDoctor by default for standard build flows in framework templates and recommended configs.

- Default: on in normal build.
- Opt-out: explicit flag/config for local fast path and emergency disable.
- Output: deterministic artifact location and minimal interaction requirements.

## 3. Rationale

- Removes conditional tooling behavior.
- Ensures diagnostics data exists for all builds by default.
- Improves debuggability and agent-assisted analysis quality.

## 4. Consequences

- Build latency increases.
- More artifacts/logs in local and CI pipelines.
- Potential friction for quick iteration loops.

## 5. Mitigations

- Add `performance.rsdoctor.enabled` (boolean, default `true`).
- Add `performance.rsdoctor.minimal` profile for lower overhead.
- Add `performance.rsdoctor.outputDir` for controlled retention.
- Add short docs for local opt-out usage in hot iteration.

## 6. Implementation Plan

1. Introduce framework config surface for RsDoctor defaults.
2. Wire automatic plugin registration in bundler chain when enabled.
3. Ensure generated output path is stable and easy to archive.
4. Add integration tests that assert RsDoctor artifacts are generated by default.
5. Update docs and migration notes.

## 7. Parallelization

- Execution mode: Parallel.
- Depends on: None.
- Blocks: None.

## 8. Acceptance Criteria

- New app builds produce RsDoctor output by default.
- Disabling via config fully removes plugin behavior.
- Existing builds remain functionally correct.
- Docs clearly explain defaults and override knobs.

## 9. Implementation Notes (2026-02-21)

- Builder now enables RsDoctor by default in production build mode.
- `performance.rsdoctor = false` remains the explicit opt-out.
- RsDoctor plugin defaults `disableClientServer` to `true` to keep diagnostics non-blocking for local and CI flows.
- Validation coverage:
  - `packages/cli/builder/tests/rsdoctor.test.ts`
  - `pnpm --filter @modern-js/builder test -- rsdoctor.test.ts`

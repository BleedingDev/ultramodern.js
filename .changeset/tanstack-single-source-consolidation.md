Consolidate all TanStack router code into `@modern-js/plugin-tanstack` and decontaminate the runtime context. This is a breaking change for `@modern-js/runtime` and `@modern-js/plugin-tanstack`; see the migration section below.

- `@modern-js/runtime` no longer ships a private copy of the TanStack runtime (`src/router/runtime/tanstack/` and the CLI `tanstackTypes` codegen are removed). `runtime.router.framework` is now resolved through a router-provider registry (`registerRouterProvider`/`resolveRouterProvider`, exported from `@modern-js/runtime/context` and `@modern-js/runtime/router/internal`): react-router registers itself as the default, `@modern-js/plugin-tanstack/runtime` registers the `tanstack` provider on import, and an unknown or unregistered framework fails loudly with instructions to install `@modern-js/plugin-tanstack`. Falsy framework values (`''`, `false`, `undefined`) keep falling back to the react-router default. Re-registering the same provider name is tolerated with keep-first semantics: a duplicate module copy (e.g. a Module Federation remote bundling its own `@modern-js/plugin-tanstack/runtime`) logs a single `console.warn` and the first registration wins instead of crashing. The registry's `globalThis` slot is keyed `Symbol.for('@modern-js/runtime:router-providers:v2')` — the version suffix isolates keep-first copies from older published `@modern-js/runtime` copies whose registry code throws on duplicate names, so mixed-version Module Federation pages cannot crash either side.
- The fork-added context fields (`routerFramework`, `routerRuntime`, `routerInstance`, `routerHydrationScript`, `routerMatchedRouteIds`, `routerServerSnapshot`, `_helmetContext`) are removed from `TRuntimeContext`/`TInternalRuntimeContext`. Router and helmet state now live in a single symbol-keyed runtime-context extension slot (`createRuntimeContextExtension`), with typed accessors (`getRouterRuntimeState`/`getRouterServerSnapshot`) shared by all router providers and the SSR pipeline. The slot is stripped from the public `RuntimeContext` value, so internal router/helmet state is no longer reachable from the public context object at all (string keys and symbol keys alike); use the accessors against the internal context.
- `@modern-js/runtime/tanstack-router` remains published as a deprecated compatibility alias for the Modern.js specific `Link`, `NavLink`, `Outlet`, `Form`, `useFetcher` and `RouteActionResponseError` bindings (plus the `Fetcher`/`FetcherState`/`FetcherSubmitOptions`/`FormProps`/`SubmitOptions`/`LinkProps`/`NavLinkProps`/`PrefetchBehavior` types). It no longer re-exports the full `@tanstack/react-router` surface; TanStack primitives now come from `@modern-js/plugin-tanstack/runtime`. The retained Modern.js bindings delegate at use time to the implementations registered by importing `'@modern-js/plugin-tanstack/runtime'` (`RouteActionResponseError` keeps class identity for `instanceof`). Using one of these bindings without `@modern-js/plugin-tanstack` installed/imported throws an actionable error.
- TanStack codegen ownership moved to the `@modern-js/plugin-tanstack` CLI plugin. `src/modern-tanstack/<entry>/router.gen.ts` and `src/modern-tanstack/register.gen.d.ts` are now generated only for entries whose routes live in the plugin's `routesDir` (file-based conventional routes), and `register.gen.d.ts` augments `'@modern-js/plugin-tanstack/runtime'` instead of `'@modern-js/runtime/tanstack-router'`. The old regex heuristic in `@modern-js/runtime` that emitted these files for *every* entry (including `createRoutes`/config-routes entries, where the route tree is a runtime function the CLI cannot see and the generated tree was empty) is gone. Generated `router.gen.ts` again emits `component: component_N` imports for routes carrying `_component`.
- `@modern-js/plugin-tanstack` reuses the canonical router runtime-state helpers and the `makeLegalIdentifier`/`getPathWithoutExt` codegen helpers from `@modern-js/runtime` instead of inlining copies, exposes a typed `getTanstackRouterState(context)` accessor, and the blocking hooks are registered solely under the `@modern-js/plugin-tanstack:*` namespace.
- `@modern-js/plugin-i18n` reads the router framework/instance through the public `getRouterRuntimeState` accessor (against the internal context) instead of duck-typing private context fields; the react-router fallback behavior is unchanged.

### Migration

- **TanStack apps must install the plugin.** `runtime.router.framework: 'tanstack'` no longer works with `@modern-js/runtime` alone. Install `@modern-js/plugin-tanstack`, add `tanstackRouterPlugin()` to `plugins` in `modern.config.ts`, and make sure `'@modern-js/plugin-tanstack/runtime'` is imported. For file-based route entries the CLI plugin injects that import automatically; apps using `createRoutes`/config-routes entries must import it themselves (e.g. first line of `src/modern.runtime.tsx`).
- **Move TanStack Router API imports to `@modern-js/plugin-tanstack/runtime`.** Imports of TanStack primitives such as `createRouter`, `createRootRoute`, `redirect` or `notFound` from `@modern-js/runtime/tanstack-router` no longer compile. The retained Modern.js compat bindings (`Link`, `NavLink`, `Outlet`, `Form`, `useFetcher` and `RouteActionResponseError`) keep compiling from the deprecated alias, but should move to `'@modern-js/plugin-tanstack/runtime'`. The alias delegates lazily, so these bindings throw a descriptive error if `'@modern-js/plugin-tanstack/runtime'` was never imported.
- **Context field reads must move to accessors.** Code reading `context.routerInstance`, `context.routerFramework`, `context.routerServerSnapshot`, `context._helmetContext` etc. must switch to `getRouterRuntimeState(internalContext)` / `getRouterServerSnapshot(internalContext)` from `@modern-js/runtime/context` (or `getTanstackRouterState` from `@modern-js/plugin-tanstack/runtime`). These fields no longer exist, and the extension slot is intentionally absent from the public `RuntimeContext` value.
- **Module Federation: sharing the provider runtime remains best practice, but it is no longer load-bearing for crash-safety.** Add `'@modern-js/plugin-tanstack/runtime'` (and `'@modern-js/runtime'`) to the `shared` config of both host and remotes to avoid double-bundling the router runtime. If copies are not shared, nothing crashes: duplicate copies of this version dedupe with keep-first semantics and a single warning, and because the registry key is versioned (`':v2'` suffix), a remote that bundles an *older* published `@modern-js/runtime` — whose registry code throws on duplicate names — keeps its own separate registry under the old key. Old and new copies register and resolve their providers independently instead of contending for one registry object, so neither side throws.
- **Regenerate or remove stale `src/modern-tanstack/*.gen.*` files.** For file-based route entries the next dev/build regenerates them (the `declare module` target changes to `'@modern-js/plugin-tanstack/runtime'`). For `createRoutes`/config-routes entries these files are no longer generated; delete the stale checked-in ones. If you want a typed `Register.router` for runtime-defined routes, declare it manually against `'@modern-js/plugin-tanstack/runtime'`.
